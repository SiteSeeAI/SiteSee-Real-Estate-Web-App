The package checksum, matching installer, canonical path checks, PHP CLI capabilities, TEST gates, file hashes, ownership/modes, path separation, disk capacity and earlier interrupted install/repair/probe journals are checked before replacement. Unknown edits and missing baseline files stop the update. Existing LF/CRLF forms are accepted and their exact bytes are backed up.

The installer parses the same package bytes whose checksum it verified. It uses a deployment lock, durable private backups, atomic replacements and a resumable journal. New dependencies are installed before their callers. Active integrity manifests are updated only for reviewed files, with established hashes checked first. Configuration flags, credentials, data, session directories, cron definitions and callback URLs are left in place. The new release record remains TEST.

SQLite backup uses the database backup API, including committed WAL rows, and checks integrity and schema/table-content fingerprints. Restoration is rehearsed into a new isolated private database. Code recovery restores original code and integrity metadata while retaining all later ledger/provider state. It never restores an old database over a newer payment or completed job. Changes to financial/provider state require review and repair forward through existing journals.

## Four release reviews

1. Dependencies and activation: the archive includes all public assets and private source needed by the original handlers. Bootstrap, renderer and CSS are installed before changed wrappers; the public loader precedes alias activation. Original signed-link, return, webhook and worker interfaces remain unchanged. PHP CLI validation does not establish PHP-FPM readiness.
2. Complete differences and data invariants: deployed code is limited to the previously reviewed bootstrap and shell changes. The installer neither initializes nor migrates the operational database. Separate synthetic records exercise protected references, vendor grants, final bills, commission and uncertain provider operations. Existing configuration/session/backup bytes and metadata remain unchanged.
3. Automated recovery: thirty-seven release cases complete on PHP 8.2 and 8.3, with thirty-six passing and one real foreign-ownership case skipped on each. The rehearsal resumes thirty durable file-replacement boundaries, checks deterministic artifacts, checksum/path/metadata refusals, concurrent deployment exclusion, WAL-inclusive restoration, exact CRLF code recovery and preservation of later successful provider state. Earlier runs remain diagnostic history. The exact frozen-commit CI subsequently executes all thirty-seven cases on both PHP versions with real privileges and no skips; historical ownership CI completes all 168 cases without skips.
4. Host and preservation: the complete command retains old backups and journal evidence. It creates no worker, callback or provider operation. The actual host preflight must establish exact deployed hashes, existing TEST configuration, runtime and exclusive worker/webhook ownership. The operator confirmed PHP 8.2 and Terminal and declined another hostname; installed TEST review will use `re.sitesee.ai` after local gates and approval of the exact server update.

The independent audit identified four issues before release: parent traversal could evade containment; historical repair/probe journals were omitted; unchanged-file active manifest hashes were not checked; and unsupported permission bits could be accepted before preparation but rejected during recovery. Each guard now rejects these cases before replacement, with focused regressions and independent verification. The exact historical CRM installer dependencies were also recovered from Git to remove a workspace-only fixture skip, retaining all original production hashes and checks.
